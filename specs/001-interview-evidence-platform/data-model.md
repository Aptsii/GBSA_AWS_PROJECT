# Data Model: Interview Evidence Platform

**Status**: Design baseline for contract freeze

**Canonical rule**: Aurora records are durable truth unless this document explicitly labels a
store as a derived view. Every tenant-owned row includes `company_id`.

## Common Conventions

| Concern | Convention |
|---|---|
| Identifier | UUIDv7-compatible string generated by the application; never derived from PII |
| Time | UTC timestamp with timezone; browser time is never authoritative |
| Tenant | `company_id` is mandatory in every tenant-owned primary/unique index and repository call |
| Version | Immutable positive integer plus source ID; used records are never edited in place |
| Optimistic concurrency | `row_version` increments on mutable aggregate changes |
| Soft status | Explicit state enum and transition time; soft deletion does not satisfy privacy deletion |
| Text security | Applicant source and answer text are excluded from operational log projections |
| Object identity | Store object key, content hash, byte size, media type and encryption metadata |
| AI provenance | Store model ID, prompt/config version, schema version and creation time |
| Idempotency | Commands and jobs persist `idempotency_key` with a unique scope constraint |

## Ownership Matrix

| Aggregate / Entity | Owner | Other lanes may store |
|---|---|---|
| Company, CompanyUser, Position, CompetencyModelVersion, EvaluationCriterion | Lane A | Stable ID and immutable version only |
| Campaign, Invitation, ConsentRecord, ApplicantProfile | Lane A | Stable ID, status projection and consent authorization result |
| Submission, SubmissionAnalysis, SubmissionChunk | Lane B | Stable ID, analysis status and source locator |
| GitRepositoryAnalysis, GitCommitAnalysis, CandidateCodeUnit | Lane B | Stable ID and source locator |
| InterviewStrategy | Lane B | Stable ID, criterion version and strategy version |
| InterviewSession, Turn, SessionCheckpoint | Lane C | Stable ID, state, sequence and completion projection |
| RecordingChunk upload state | Lane C | Stable media locator and session-clock range |
| TranscriptSegment, RecordingAsset, SessionEvent | Lane D | Lane C may emit provisional transcript/media events |
| Report, ReportItem, Evidence, HumanReview | Lane D | Stable ID and readiness/status projection |
| RetentionPolicy | Lane A | Lane D consumes an immutable policy snapshot |
| DeletionRequest, DeletionManifest, DeletionTarget | Lane D | Target lanes update only their target receipt/result |
| AuditEvent | Lane A technical primitive | Each lane appends through the public audit interface |
| OutboxEvent, ProcessedMessage | Integration-owned primitive | Each lane writes through shared interface |

### DeletionRequest, DeletionManifest and DeletionTarget

| Entity | Key fields and rules |
|---|---|
| `DeletionRequest` | tenant/applicant/invitation scope, reason, requester type/ID, requested time, policy snapshot, status |
| `DeletionManifest` | request ID, manifest version, expected target count, completed count, verification status |
| `DeletionTarget` | target store/type/ID, owner lane, status, attempts, last error code, verified absent time |

The request is `completed` only when every target is `verified_absent`. A failed store keeps the
request in `partially_completed` or `retrying`.

## Shared Technical Entities

### OutboxEvent

`outbox_event_id`, `company_id`, aggregate type/ID, event type/version, payload containing IDs
only, occurred time, trace ID, publish status and attempt count. Created in the aggregate transaction.

### ProcessedMessage

Consumer name, event ID, event version, idempotency key, first processed time and outcome digest.
Unique on consumer plus event ID/version.

### AuditEvent

Tenant, opaque actor ID/type, action, resource type/ID, result, occurred time, request/trace ID and
sanitized metadata. It never contains applicant source or answer text.

## State Machines

### Invitation

```text
invited -> identity_verified -> consented -> materials_submitted -> analyzing
         -> ready -> interviewing -> interrupted -> interviewing
         -> completed -> reviewed
```

Additional terminal states: `expired`, `revoked`, `deleted`. Expired/revoked invitations cannot
re-enter an active state. `interrupted` returns only to `interviewing` through a verified
checkpoint.

### Interview Session

```text
preparing -> in_progress -> awaiting_answer -> preparing_question -> in_progress
in_progress | awaiting_answer | preparing_question -> paused
paused -> in_progress
in_progress | awaiting_answer -> completed -> report_generating -> reviewable
```

Every accepted transition increments `session_sequence`. Late or repeated commands with an older
expected sequence return the current snapshot without rolling state backward.

### Analysis Job

```text
queued -> running -> ready
                  -> partial
                  -> retrying -> running
                  -> failed
ready | partial -> superseded
```

### Deletion

```text
requested -> enumerating -> deleting -> verifying -> completed
                                |           |
                                +-> retrying+
                                +-> partially_completed
```

## DynamoDB Hot View

```text
PK: SESSION#{interview_session_id}
SK:
  META
  CHECKPOINT#{zero_padded_sequence}
  TURN#{zero_padded_sequence}
  SUMMARY#{start_sequence}#{end_sequence}
```

Every item includes `company_id`, durable `turn_id` or checkpoint ID, schema version, last
reconciled outbox event and TTL. The view can be rebuilt from Aurora and transcript objects.

```text
companies/{company_id}/invitations/{invitation_id}/
  submissions/{submission_id}/original/{opaque_object_id}
  submissions/{submission_id}/derived/{analysis_version}/{opaque_object_id}

  submissions/{submission_id}/github/{repository_id}/commits/{commit_sha}/{opaque_object_id}

  sessions/{session_id}/recording/final/{asset_version}/{opaque_object_id}
```

Names and emails never appear in keys. Every key is authorized against the company, invitation and
session in the current tenant context.

## Cross-Entity Integrity Rules

1. A Campaign, Invitation, Strategy, Session, ReportItem and Evidence chain resolves to one identical
   `company_id` and `competency_model_version_id`.
2. A Strategy cannot become ready without a valid consent authorization snapshot.
3. A Session cannot start unless the invitation is active and the Strategy is ready or explicitly
   partial with acknowledged impact.
4. A SourceReference may point to a SubmissionChunk or CandidateCodeUnit; Evidence may point only to
   a final applicant Turn and valid transcript/video interval.
5. Search IDs and hot-view items are derived references, never cascading authorities.
6. Technical-failure intervals cannot be used by Evidence.
7. Report AI originals and human review rows are append-only.
8. Deletion enumeration starts from durable relational records and includes all known derived IDs.
