# Feature Specification: Interview Evidence Platform

**Feature Branch**: `001-interview-evidence-platform`

**Created**: 2026-08-14

**Status**: Ready for Planning

**Input**: User description: "기획서 v1.4를 기준으로 IT/개발 직군 특화 AI 구조화
면접 플랫폼을 정의하고, 네 명이 병렬 개발한 결과를 안전하게 통합할 수 있는 명확한
스펙으로 전환한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기업이 일관된 면접 기준을 설계하고 지원자를 초대한다 (Priority: P1)

기업은 채용 포지션, 인재상, 평가 기준, 공통 질문, 금지 영역과 AI 면접관의 진행
방식을 설정한다. 설정을 게시한 뒤 지원자를 개별 또는 일괄 등록하고, 만료되는 개인별
면접 링크와 진행 상태를 관리한다.

**Why this priority**: 모든 분석, 면접, 평가가 동일한 기업 기준과 유효한 초대에서
출발하므로 나머지 여정의 기준점이다.

**Independent Test**: 새 기업 공간에서 포지션과 평가 기준 버전을 만들고 캠페인을
게시한 뒤 테스트 지원자를 초대하여, 고유 링크 발급과 상태 이력까지 독립적으로 확인할
수 있다.

**Acceptance Scenarios**:

1. **Given** 인증된 기업 사용자가 빈 기업 공간에 접속한 상태에서, **When** 포지션과
   평가 항목별 관찰 기준을 저장하면, **Then** 변경 불가능한 평가 기준 버전이 생성되고
   캠페인이 그 버전을 참조한다.
2. **Given** 필수 평가 기준과 금지 질문이 완성된 캠페인에서, **When** 기업이 지원자를
   등록하면, **Then** 지원자별 만료 링크가 발급되고 초대됨 상태와 발급 시점이 기록된다.
3. **Given** 다른 기업에 같은 이메일의 사용자가 존재할 때, **When** 한 기업이 포지션과
   초대를 조회하면, **Then** 자신의 기업 데이터만 볼 수 있다.
4. **Given** 게시된 캠페인에 지원자가 이미 연결된 상태에서, **When** 기업이 평가
   기준을 변경하면, **Then** 기존 세션의 기준은 유지되고 새 버전이 이후 초대에 적용된다.

### User Story 2 - 지원자가 동의하고 자료를 제출해 면접 전략을 준비한다 (Priority: P1)

지원자는 계정 생성 없이 개인 링크로 본인 확인을 하고 개인정보 처리, 녹화와 AI 활용
범위에 동의한다. 이력서, 자기소개서, PDF 문서와 공개 코드 저장소를 제출하면 시스템은
자료의 주장과 코드 기여 후보를 분석해 공통 평가축 안의 개인별 검증 포인트를 준비한다.

**Why this priority**: 제출 자료는 개인화된 기술 면접의 출발점이며, 동의와 출처
추적성은 제품 신뢰의 필수 조건이다.

**Independent Test**: 미리 준비된 캠페인 초대로 본인 확인과 동의를 완료하고 문서와
공개 테스트 저장소를 제출하여, 성공·부분 성공·실패 자료의 상태와 출처가 있는 면접
전략을 독립적으로 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 유효하고 사용 전인 초대 링크에서, **When** 지원자가 본인 확인과 필수
   동의를 완료하면, **Then** 링크의 원문 비밀값은 노출되지 않고 해당 지원자 범위의
   준비 세션이 생성된다.
2. **Given** 동의가 완료되지 않은 상태에서, **When** 자료 분석 또는 녹화 시작을
   요청하면, **Then** 처리가 거부되고 동의가 필요한 이유가 표시된다.
3. **Given** 문서와 공개 저장소가 제출된 상태에서, **When** 분석이 완료되면,
   **Then** 주장의 출처 위치, 코드 기여 신뢰도, 자료 간 충돌 후보와 검증 포인트가
   평가 기준 버전에 연결된다.
4. **Given** 여러 자료 중 하나의 분석이 실패했을 때, **When** 나머지 자료와 공통
   평가 기준으로 전략을 만들 수 있으면, **Then** 준비는 부분 완료되고 실패 대상,
   원인과 면접 영향이 지원자와 기업에 구분되어 표시된다.
5. **Given** 관련성이 낮거나 기여가 불확실한 코드만 검색된 경우, **When** 전략이
   생성되면, **Then** 해당 내용을 지원자의 사실로 단정하지 않고 확인 질문 또는
   자료 근거 없음으로 남긴다.

### User Story 3 - 지원자가 복구 가능한 실시간 구조화 면접을 완료한다 (Priority: P1)

지원자는 장비를 점검한 뒤 AI임을 명확히 고지받고 면접을 시작한다. 공통 평가축과
지원자별 검증 포인트에 따라 짧은 질문을 듣고 답하며, 답변 완료를 직접 선택한다.
기술 장애가 발생하면 마지막 확정 지점부터 중복 없이 재개한다.

**Why this priority**: 실제 답변에서 검토 가능한 근거를 만드는 과정이 제품의 핵심
가치이며, 장애를 역량으로 오해하지 않는 복구 능력이 필수다.

**Independent Test**: 준비된 면접 전략과 지원자 세션으로 질문-답변-꼬리질문 흐름을
완료하고, 중간 연결 중단 뒤 재접속하여 중복 답변 없이 같은 세션을 종료할 수 있다.

**Acceptance Scenarios**:

1. **Given** 장비 점검과 전략 준비가 끝난 지원자가, **When** 면접 시작을 선택하면,
   **Then** AI 고지와 진행 안내 후 아직 확인하지 않은 공통 평가 항목의 질문이 제시된다.
2. **Given** 지원자가 답변 중일 때, **When** 답변 완료를 한 번 이상 선택하면,
   **Then** 동일한 요청은 한 번만 확정되고 하나의 답변과 하나의 다음 질문만 생성된다.
3. **Given** 직전 답변이 모호하거나 제출 자료와 충돌할 때, **When** 후속 질문을
   선택하면, **Then** 금지 영역을 피하면서 하나의 짧은 확인 질문이 제시되고 대상 평가
   항목은 바뀌지 않는다.
4. **Given** 검색 기능을 일시적으로 사용할 수 없을 때, **When** 다음 질문이 필요하면,
   **Then** 자료를 꾸며내지 않고 공통 기준과 최근 답변만으로 면접을 계속하며 제한
   상태를 기록한다.
5. **Given** 질문 또는 답변 중 네트워크나 외부 서비스 장애가 발생할 때, **When**
   지원자가 재접속하면, **Then** 마지막 확정 답변, 미완료 답변, 녹화 구간과 질문
   상태를 확인해 안전한 지점부터 재개한다.
6. **Given** 면접 종료 조건이 충족되었을 때, **When** 지원자가 추가 설명 또는 정정
   기회를 마치면, **Then** 세션이 완료되고 더 이상 답변을 변경할 수 없으며 후처리
   상태가 표시된다.

### User Story 4 - 기업이 답변 근거를 검토하고 사람이 최종 판단한다 (Priority: P1)

기업은 완료된 면접의 요약, 평가 상태, 질문·답변, 자막과 영상을 한 화면에서 검토한다.
각 평가의 실제 답변 근거와 자료 출처를 구분해 확인하고, AI 원본을 보존한 채 수정 의견,
메모, 북마크와 후속 질문을 기록한다. 최종 채용 상태는 사람만 변경한다.

**Why this priority**: 검토자가 AI의 단정을 받는 것이 아니라 근거를 빠르게 확인하고
책임 있게 판단하는 것이 제품의 최종 가치다.

**Independent Test**: 사전에 준비된 완료 면접과 미디어를 열어 평가 항목에서 답변과
영상 시점으로 이동하고, AI 평가 수정 이력과 사람의 최종 상태 기록 및 삭제 요청까지
독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 리포트 생성이 끝난 면접에서, **When** 기업이 평가 항목을 열면,
   **Then** 상태, 관찰 내용, 판단 이유, 근거 충분도와 연결된 실제 답변·자막·영상
   구간을 확인할 수 있다.
2. **Given** 자료에만 존재하고 실제 답변 근거가 없는 주장에 대해, **When** 리포트가
   생성되면, **Then** 해당 항목은 확인됨 또는 부분 확인으로 저장되지 않는다.
3. **Given** 기업이 AI 평가를 수정할 때, **When** 수정 사유를 저장하면, **Then** AI
   원본, 사람 수정본, 수정 주체와 시점이 모두 보존된다.
4. **Given** 최종 채용 상태 변경을 AI 또는 자동 작업이 요청할 때, **When** 권한을
   검사하면, **Then** 요청이 거부되고 사람의 명시적 행동만 기록된다.
5. **Given** Evidence 링크를 선택했을 때, **When** 원본 미디어가 유효하면, **Then**
   연결된 자막과 영상 구간 재생이 2초 안에 시작된다.
6. **Given** 보관 기간 만료 또는 유효한 삭제 요청이 발생했을 때, **When** 삭제가
   완료되면, **Then** 원본, 파생 자료, 검색 표현, 최근 문맥과 요약의 삭제 결과가
   저장소별로 검증된다.

### Edge Cases

- 만료, 재사용 또는 변조된 지원자 링크로 접근하면 어떠한 개인정보도 노출하지 않고
  안전한 재안내 경로만 제공한다.
- 같은 답변 완료 요청, 업로드 조각 또는 작업 메시지가 반복 전달되어도 결과가
  중복 생성되지 않는다.
- 지원자 자료가 없거나 모두 분석에 실패하면 공통 평가 기준만으로 진행 가능 여부를
  명시하고 기업과 지원자에게 영향 범위를 알린다.
- 음성 인식 신뢰도가 낮은 구간은 사실로 확정하지 않고 원본 오디오와 사람 확인
  필요 상태를 연결한다.
- 질문 생성 결과가 금지 주제, 복수 질문, 중복 질문 또는 평가축 변경을 포함하면
  차단하고 안전한 대체 질문 또는 일시 중단으로 전환한다.
- 녹화 조각 일부가 누락되어도 수신한 구간을 보존하고 누락 구간이 평가 Evidence에
  포함되지 않게 한다.
- 한 저장소의 삭제가 실패하면 전체 삭제를 완료로 표시하지 않고 성공·실패 저장소와
  재시도 상태를 보존한다.
- 동일한 이름, 이메일 또는 코드 작성자 정보만으로 지원자 기여를 확정하지 않는다.
- 객관적 진행 이벤트와 표정·시선·억양 등의 특성은 역량 점수에 합산되지 않는다.
- 평가 기준이 면접 도중 새 버전으로 변경되어도 시작 시 고정한 버전을 끝까지 사용한다.

## Requirements *(mandatory)*

### Functional Requirements

#### 제품 범위와 역할

- **FR-001**: 시스템은 한국어를 사용하는 IT/개발 직군 채용의 기업과 지원자 여정을
  제공해야 한다.
- **FR-002**: 시스템은 AI가 면접 진행, 기록, 요약과 평가 보조를 수행한다는 사실을
  지원자에게 면접 전에 명확히 알려야 한다.
- **FR-003**: 시스템은 AI 또는 자동 작업이 합격, 불합격 또는 그에 준하는 최종 채용
  상태를 변경할 수 없게 해야 한다.
- **FR-004**: 시스템은 객관적 진행 이벤트를 직무 역량 평가 입력과 분리하고, 외모,
  표정, 시선, 억양, 성별 또는 연령에서 성격·정직성·역량을 추론하지 않아야 한다.
- **FR-005**: 시스템은 기업별 데이터를 모든 사용자·작업·검색·파일 접근에서
  격리해야 한다.

#### 기업·채용 기준과 초대

- **FR-006**: 기업 사용자는 이메일과 비밀번호로 인증하고 자신의 기업 공간에만
  접근할 수 있어야 한다.
- **FR-007**: 기업은 포지션, 직무 설명, 인재상, 필수·우대 역량을 정의할 수 있어야 한다.
- **FR-008**: 기업은 평가 항목별 중요도, 좋은 답변, 부족한 답변, 판단 유보 기준과
  공통 질문을 정의할 수 있어야 한다.
- **FR-009**: 기업은 금지 질문과 민감 영역, 면접 시간, 진행 분위기, AI 면접관의
  이름·외형·음성·말투를 설정하고 미리 볼 수 있어야 한다.
- **FR-010**: 시스템은 게시 또는 사용된 평가 기준을 버전으로 고정하고, 이후 변경이
  기존 초대와 면접의 평가축을 바꾸지 않게 해야 한다.
- **FR-011**: 기업은 지원자를 개별 또는 일괄 등록하고, 지원자별로 충분히 무작위이며
  만료되고 범위가 제한된 고유 링크를 발급할 수 있어야 한다.
- **FR-012**: 시스템은 초대부터 검토 완료까지 모든 상태 변경의 시점과 수행 주체를
  기록해야 한다.

#### 지원자 온보딩과 자료 분석

- **FR-013**: 지원자는 회원가입 없이 유효한 고유 링크, 본인 확인과 만료되는 세션으로
  자신의 면접에 접근할 수 있어야 한다.
- **FR-014**: 시스템은 개인정보 처리, 녹화, AI 분석, 보관 기간과 삭제 방법에 대한
  필수 동의를 기록해야 한다.
- **FR-015**: 시스템은 유효한 동의가 없으면 자료 분석, 녹화와 AI 평가를 시작하지
  않아야 한다.
- **FR-016**: 지원자는 자기소개서, 이력서, PDF 포트폴리오·기술 문서와 공개 코드
  저장소 또는 공개 산출물 주소를 제출할 수 있어야 한다.
- **FR-017**: 시스템은 제출 원본의 무결성, 처리 상태, 출처 위치와 파생 결과의 버전을
  추적해야 한다.
- **FR-018**: 시스템은 문서에서 경험, 역할, 성과, 기술 선택, 구체성 부족과 자료 간
  일치·충돌 후보를 추출해야 한다.
- **FR-019**: 시스템은 공개 코드 저장소에서 지원자 기여 후보를 커밋과 변경 코드
  단위로 분석하고, 전체 코드 문맥·관련 테스트·현재 상태와 연결해야 한다.
- **FR-020**: 시스템은 코드 기여를 단정하지 않고 기여 범위와 신뢰도를 표시해야 한다.
- **FR-021**: 시스템은 기업 평가 기준, 공통 주제, 개인별 검증 포인트, 꼬리질문 방향,
  미확인 Evidence와 시간 예산을 포함한 버전 있는 면접 전략을 만들어야 한다.
- **FR-022**: 시스템은 자료 일부가 실패해도 가능한 결과로 부분 완료하고 실패 대상,
  원인과 영향 범위를 명확히 표시해야 한다.

#### 실시간 면접과 복구

- **FR-023**: 지원자는 면접 전에 카메라, 마이크, 네트워크와 진행 절차를 점검할 수
  있어야 한다.
- **FR-024**: 시스템은 공통 평가 항목과 지원자별 검증 포인트를 결합하되 평가축을
  지원자별로 변경하지 않아야 한다.
- **FR-025**: 시스템은 한 번에 하나의 짧고 명확한 질문을 제시하고, 지원자가 불이익
  없이 재설명을 요청할 수 있게 해야 한다.
- **FR-026**: 시스템은 지원자가 `답변 완료`를 선택했을 때만 답변을 확정하고 자발적
  재녹음은 허용하지 않아야 한다.
- **FR-027**: 시스템은 기술 장애에 따른 재시도와 복구를 자발적 재녹음과 구분해야 한다.
- **FR-028**: 시스템은 최근 대화, 오래된 대화 요약, 미확인 평가 항목, 남은 시간과
  관련 자료를 사용해 다음 질문을 선택해야 한다.
- **FR-029**: 시스템은 금지 질문, 직무와 무관한 개인정보 추론, 중복 질문, 복수 질문과
  평가축 변경을 결정적으로 차단해야 한다.
- **FR-030**: 시스템은 질문에 사용한 자료 출처와 검색·생성 버전을 저장해야 한다.
- **FR-031**: 시스템은 질문·답변, 확정 자막, 녹화 구간과 상태 순서를 하나의 세션
  시간축으로 연결해야 한다.
- **FR-032**: 시스템은 답변 확정, 상태 전이, 업로드와 작업 재처리를 멱등하게 처리해야 한다.
- **FR-033**: 시스템은 허용된 면접 상태 전이만 수락하고 각 전이에 단조 증가하는
  버전과 순서를 부여해야 한다.
- **FR-034**: 시스템은 연결 또는 외부 기능 실패 후 마지막 확정 Turn과 체크포인트부터
  중복 없이 재개해야 한다.
- **FR-035**: 시스템은 검색, 음성 합성 또는 최근 문맥 보조 기능이 실패할 때 정의된
  제한 모드와 명확한 사용자 안내를 제공해야 한다.
- **FR-036**: 시스템은 지원자가 종료 전에 정정 또는 추가 설명할 기회를 갖게 해야 한다.

#### 타임라인, Evidence와 사람 검토

- **FR-037**: 시스템은 전체 녹화와 음성, 화자별 자막, 질문·답변과 객관적 진행 이벤트를
  세션 타임라인으로 제공해야 한다.
- **FR-038**: 기업은 질문, 평가 항목, 자막 또는 키워드에서 연결된 영상 시점으로
  이동할 수 있어야 한다.
- **FR-039**: 시스템은 평가 항목마다 확인됨, 부분 확인, 근거 부족, 추가 확인 필요 중
  하나의 상태를 사용해야 한다.
- **FR-040**: 확인됨과 부분 확인 상태는 실제 지원자 답변, 자막 구간, 영상 구간, 평가
  기준 버전, 관찰 내용, 판단 이유와 근거 충분도를 가진 Evidence를 하나 이상 요구해야 한다.
- **FR-041**: 시스템은 질문 생성을 위한 Source Reference와 평가를 위한 Evidence를
  구분해 저장하고 표시해야 한다.
- **FR-042**: 시스템은 리포트에 요약, 역량별 관찰, 강점, 우려, 미확인 사항, 불확실성과
  사람 면접용 후속 질문을 제공해야 한다.
- **FR-043**: 기업은 AI 평가를 수정하거나 무시하고 메모와 북마크를 남길 수 있어야 한다.
- **FR-044**: 시스템은 AI 원본, 사람 수정본, 수정 사유, 주체와 시점을 변경 불가능한
  이력으로 보존해야 한다.
- **FR-045**: 사람 권한을 가진 기업 사용자만 최종 채용 상태를 명시적으로 기록할 수
  있어야 한다.

#### 보안, 개인정보와 품질

- **FR-046**: 시스템은 기업별 보관 기간을 적용하고 기본값을 6개월로 제공해야 한다.
- **FR-047**: 시스템은 보관 만료 또는 삭제 요청 시 원본과 파생 자료를 저장소별로
  삭제하고 완료 여부를 검증해야 한다.
- **FR-048**: 시스템은 지원자 자료·영상·리포트의 조회, 수정, 다운로드와 삭제를
  감사 기록으로 남겨야 한다.
- **FR-049**: 시스템은 자격 증명, 원문 답변·문서, 접근 비밀값과 임시 다운로드 주소를
  운영 로그에 기록하지 않아야 한다.
- **FR-050**: 시스템은 외부 기능 실패에 대해 시간 제한, 제한된 재시도, 실패 격리와
  사람에게 이해 가능한 상태를 제공해야 한다.
- **FR-051**: 시스템은 질문 관련성, 검색 관련성, Evidence 연결률, 면접 단계별 지연,
  장애와 복구 결과를 설정 버전별로 측정해야 한다.
- **FR-052**: 시스템은 고정 자료와 기대 검증 포인트를 가진 회귀 사례로 질문, 검색,
  평가와 격리를 반복 검증할 수 있어야 한다.

### Key Entities

- **Company**: 하나의 격리된 기업 채용 공간과 보관 정책을 나타낸다.
- **CompanyUser**: 기업에 속해 인증하고 사람 검토와 최종 상태를 기록하는 주체다.
- **Position**: 직무 설명과 채용 범위를 나타낸다.
- **CompetencyModelVersion**: 특정 시점에 고정된 인재상과 평가축 버전이다.
- **EvaluationCriterion**: 역량, 관찰 기준, 중요도와 판단 상태 규칙이다.
- **Campaign**: 포지션, 평가 기준 버전과 면접 설정을 묶어 게시한 채용 단위다.
- **Invitation**: 지원자 한 명에게 발급된 만료·상태·범위 제한 접근 권한이다.
- **ConsentRecord**: 지원자가 동의한 처리 목적, 범위, 문구 버전과 시점이다.
- **ApplicantProfile**: 지원자의 정확한 식별 정보와 제출 기술 목록이다.
- **Submission**: 지원자가 제출한 문서, 코드 저장소 또는 공개 산출물과 처리 상태다.
- **SubmissionAnalysis**: 제출 자료에서 파생된 주장, 충돌, 청크와 검증 포인트 버전이다.
- **GitCommitAnalysis**: 지원자 기여 후보 커밋과 변경 내용, 출처 및 신뢰도다.
- **CandidateCodeUnit**: 변경된 코드와 그 전체 문맥, 관련 테스트 및 소유 영역이다.
- **InterviewStrategy**: 고정 평가축 안의 공통 주제, 개인 검증 포인트와 시간 예산이다.
- **InterviewSession**: 상태, 순서, 체크포인트와 시작·완료 시점을 가진 면접 실행이다.
- **Turn**: 확정된 질문 또는 지원자 답변과 세션 순서를 나타낸다.
- **SourceReference**: 질문이 참조한 제출 자료 위치와 검색·생성 버전이다.
- **Recording**: 분할 녹화 원본과 최종 재생 자료, 무결성과 세션 시계 정보다.
- **TranscriptSegment**: 화자, 텍스트, 신뢰도와 시작·종료 시점을 가진 자막 구간이다.
- **SessionEvent**: 기술 장애 또는 객관적 진행 관찰과 평가 제외 여부다.
- **Report**: AI 원본과 버전을 가진 면접 검토 결과다.
- **ReportItem**: 평가 항목별 상태, 관찰, 판단 이유와 불확실성이다.
- **Evidence**: 실제 지원자 답변, 자막·영상 구간과 평가 기준을 연결한 근거다.
- **HumanReview**: 사람 수정, 메모, 북마크, 후속 질문과 최종 상태 이력이다.
- **DeletionManifest**: 원본과 모든 파생 자료의 저장소별 삭제 상태와 재시도 이력이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 별도 교육을 받지 않은 기업 사용자가 포지션, 평가 기준과 캠페인을
  30분 안에 게시할 수 있다.
- **SC-002**: 파일럿 기업의 80% 이상이 생성된 질문 포인트를 해당 직무와 관련 있다고
  평가한다.
- **SC-003**: 기업 사용자가 지원자 한 명의 핵심 면접 내용을 파악하는 시간이 전체
  영상을 처음부터 검토할 때보다 50% 이상 줄어든다.
- **SC-004**: 주요 AI 평가의 95% 이상이 유효한 실제 답변 Evidence와 연결된다.
- **SC-005**: 완료된 면접의 90% 이상에서 모든 필수 평가 항목에 유효 Evidence 또는
  명시적인 근거 부족 상태가 존재한다.
- **SC-006**: 파일럿 기업 사용자의 80% 이상이 결과를 충분히 검토할 수 있다고 응답한다.
- **SC-007**: 시작된 면접의 85% 이상이 기술적 중단 없이 완료된다.
- **SC-008**: 중단 후 재개가 가능한 세션의 90% 이상이 중복 Turn 없이 복구된다.
- **SC-009**: 지원자의 80% 이상이 질문을 이해했고 자신의 경험을 설명할 기회가
  충분했다고 응답한다.
- **SC-010**: 모든 면접에서 시작 전에 수집, 녹화, AI 활용, 보관과 삭제 안내가
  제시되고 유효한 동의가 기록된다.
- **SC-011**: 자동 합격·불합격 또는 자동 최종 채용 상태 변경이 0건이다.
- **SC-012**: Evidence 선택 후 유효한 영상 구간의 재생이 2초 안에 시작된다.
- **SC-013**: 기업 5개사, 동시 면접 5건, 누적 수백 건의 파일럿 조건에서 종단 여정이
  데이터 혼선 없이 완료된다.
- **SC-014**: 모든 격리 검증에서 다른 기업 또는 지원자의 데이터가 반환되는 사례가 0건이다.
- **SC-015**: 완료된 삭제 작업의 100%에서 원본, 파생 자료, 검색 표현, 요약과 최근
  문맥의 부재가 검증된다.
- **SC-016**: 고정 회귀 사례에서 근거 없는 평가가 확인됨 또는 부분 확인 상태로
  저장되는 사례가 0건이다.

## Assumptions

- 1차 제품은 기업 1~5개사, 동시 면접 1~5건, 누적 수백 건의 파일럿을 대상으로 한다.
- 지원자는 데스크톱 또는 노트북의 최신 브라우저, 카메라와 마이크를 사용할 수 있다.
- 지원 자료의 코드 저장소는 인증 없이 접근 가능한 공개 저장소만 포함한다.
- UI, 면접 대화와 리포트는 한국어 전용이며 코드와 기술 용어에는 영문이 섞일 수 있다.
- 기업 내부의 세밀한 역할별 권한, 다국어, 비IT 직군, 비공개 저장소, 광범위한
  ATS/HRIS 연동, SSO와 실사형 아바타는 1차 범위에서 제외한다.
- 자료의 완성도는 평가 점수가 아니며, 실제 면접 답변만 역량 Evidence가 될 수 있다.
- 자료 분석이 부분 실패해도 공통 평가 기준과 성공한 자료로 안전하게 진행할 수 있다.
- 보관 기간은 기업이 변경할 수 있고 별도 설정이 없으면 6개월을 사용한다.
- 최종 채용 판단과 그 책임은 항상 기업의 사람에게 있다.
